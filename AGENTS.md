# Buzzword weather

A Streamlit toy from ahmedavais.com: how often Hacker News mentions each engineering buzzword, and its weather now.
`README.md` explains how it works and how it's put together; read it before changing behavior.

## Checks

- CI (`.github/workflows/ci.yml`) runs on every pull request and push to main: `uv run ruff check .` and
  `uv run pytest`, which includes the sensors in `sensors/`. Run both before calling any change done.
- `uv run pytest -m integration` checks the real Hacker News search API. CI leaves it out.
- Duplication: the `duplication` job in `.github/workflows/ci.yml`, shared from
  [karkhana](https://github.com/ahmedavais/karkhana), fails when a change adds code duplicated elsewhere in the repo,
  tests included. `.jscpd.json` lists the lock and generated files it skips.
- Habit Hooks: `.habit-hooks/config.toml` opts this repo into Ahmed's global Claude Code Stop hook. When Claude stops,
  it checks what the branch changed for structural smells (too many parameters, high complexity, oversized functions and
  files, unused imports and dependencies) and hands Claude a coaching guide for each. Habit Hooks picks the Ruff rules;
  the limits are Ruff's defaults, such as 5 parameters, because this repo's Ruff config sets none. It needs `uv sync`,
  so deptry is in `.venv`.
- Adversarial review: `.github/workflows/adversarial-review.yml` has Claude Code review every pull request with the
  shared workflow and brief from [karkhana](https://github.com/ahmedavais/karkhana). Comments only. The reviewer takes
  this repo's checks and conventions from this file, so keep them current here.
- Dependency updates: `renovate.json` follows the shared Renovate policy in
  [karkhana](https://github.com/ahmedavais/karkhana), for `pyproject.toml` and `uv.lock`, `.python-version` and the
  Actions. Patch and minor updates arrive as one pull request on Mondays and merge themselves once every check passes,
  which deploys them. The lock file refresh and any major arrive the same day and stay open, assigned to Ahmed. When
  CI fails on one, the `failed-update-alarm` job in `.github/workflows/ci.yml` assigns it to Ahmed; its `needs` lists
  every other pull request job, so add a new job there too. The adversarial review skips a Renovate pull request only
  when it changes nothing but dependency manifests and lock files.
- The refresh Action runs the tests before it commits a new almanac. The weekly words Action runs the integration
  tests and then the tests before it commits `weekly_words.json`, and before each candidate pull request it opens.
  Keep-awake visits the app every 6 hours.

## Conventions

- Community Cloud deploys main on its own, so a push or merge to main is a deploy.
- Logic lives in `buzzword_weather/` as small modules, each with a `*_test.py` next to it. `app.py` reloads the code after a
  deploy, then only renders.
- Tests are sociable and state-based. No mocking libraries: outside systems are nullables with `create()` and
  `create_null()`, as `hacker_news.py` and `http_client.py` do. Tests never touch the network unless marked
  `integration`.
- No comments in code. Names and small functions carry the meaning.
- Counts are mentions per 10,000 posts, never raw counts: Hacker News posts far more now than in 2008. Weekly words
  are per 10,000 story titles.
- Ruff is lint only, no formatter.
- New features start as an [OpenSpec](https://github.com/Fission-AI/OpenSpec) change in `openspec/changes/` (`/opsx:propose`,
  then `/opsx:apply`, then `/opsx:archive` once it ships). `.claude/skills/openspec-*` and `.claude/commands/opsx/` are
  generated by `openspec init`. `openspec/specs/` holds the living specs. Archived changes in `openspec/changes/archive/`
  are a frozen record, so `.jscpd.json` skips them.
- `playground/` is for throwaway exploration. Ahmed's global gitignore keeps it out of git, not this repo's `.gitignore`.
